Penjelasan Detail Arsitektur Berlapis

Dokumentasi Teknis Proyek Management System

Arsitektur Berlapis (sering dikaitkan dengan Clean Architecture atau Onion Architecture) adalah pola desain perangkat lunak yang memisahkan kode menjadi beberapa lapisan logis. Tujuannya adalah untuk membuat sistem yang:

  1. Mudah Diuji (Testable): Logika bisnis bisa dites tanpa database atau server web.
  2. Independen: UI, Database, dan Framework bisa diganti tanpa mengubah aturan bisnis inti.
  3. Terstruktur: Setiap kode memiliki "rumah" yang jelas sesuai tanggung jawabnya.

Dalam proyek ini, arsitektur dibagi menjadi 4 lapisan utama:

1. Domain Layer (Inti Bisnis)

Lokasi: src/domain

Ini adalah jantung dari aplikasi. Lapisan ini berisi aturan bisnis murni dan tidak boleh bergantung pada lapisan lain. Ia tidak tahu apa itu database, HTTP, atau JSON.

  • Isi Utama:
    • Entities: Objek bisnis utama yang memiliki ID dan siklus hidup (contoh: Asset, Employee).
    • Value Objects: Objek tanpa ID yang didefinisikan oleh nilainya.
    • Repository Interfaces: Kontrak/interface yang mendefinisikan apa yang bisa dilakukan.
  • Contoh: src/domain/entities/asset.rs mendefinisikan struktur Asset.

2. Application Layer (Orkestrator)

Lokasi: src/application

Lapisan ini menjembatani dunia luar dengan Domain. Ia berisi "Use Cases" atau alur cerita pengguna.

  • Tanggung Jawab:
    • Menerima input dari API (DTO).
    • Memanggil Repository untuk mengambil data Domain.
    • Mengeksekusi logika bisnis pada Domain Entity.
  • Isi Utama: Services (AssetService), DTOs.

3. Infrastructure Layer (Teknis & Tools)

Lokasi: src/infrastructure

Lapisan ini berisi detail teknis dan implementasi konkret. Ini adalah "tukang" yang melakukan pekerjaan kotor.

  • Tanggung Jawab: Berbicara dengan Database (SQLx), Email, PDF.
  • Isi Utama: Repositories (PostgresAssetRepository), Adapters.

4. API / Interface Layer (Pintu Gerbang)

Lokasi: src/api

Lapisan terluar yang berinteraksi langsung dengan pengguna atau sistem lain.

  • Tanggung Jawab: Menerima request HTTP, Validasi JSON, Mengembalikan Response.
  • Isi Utama: Routes, Handlers, Middleware.

Analogi Hukum Negara Prosedur Birokrasi Jalan & Listrik Loket Pelayanan

Analogi Dunia Nyata: Restoran Modern 🍽️

1. API Layer = Pelayan (Waiter) 🤵

Menyambut tamu, mencatat pesanan, mengantar makanan. Mereka tidak memasak, hanya penghubung.

2. Application Layer = Head Chef / Manajer Dapur 👨‍🍳

Menerima pesanan, berteriak "Satu Nasi Goreng!", mengatur tim. Mereka mengorkestrasi alur masak.

3. Domain Layer = Buku Resep & SOP 📖

Menentukan apa itu Nasi Goreng (harus ada nasi, kecap). Resep ini tetap sama mau dimasak pakai kompor gas atau arang.

4. Infrastructure Layer = Kompor & Kulkas 🍳

Alat teknis. Chef bilang "Dinginkan", Kulkas melakukannya. Chef tidak perlu tahu cara kerja freon.
